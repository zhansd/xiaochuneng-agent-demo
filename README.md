# 小储能Agent v5.7 - 储能光伏行业垂直多智能体系统

基于小米MIMO大模型驱动的多Agent协作系统，面向储能/光伏行业提供智能分析、投资计算、方案生成等一站式服务。

---

## 一、项目背景

储能和光伏行业涉及大量专业计算（投资回报、装机容量、电价分析、碳减排核算）、政策检索、设备选型、方案撰写等工作。传统方式依赖工程师手工计算和查阅资料，效率低、门槛高、容易出错。

本项目以小米MIMO v2 Pro为推理核心，构建了一套真正的多Agent协作系统，让非专业用户通过自然语言即可完成储能/光伏项目的全套分析和方案生成。最终目标是基于MIMO打造储能光伏行业的垂直大模型。

## 三、核心特性

### 3.1 多Agent动态协调

Orchestrator不使用固定流程图，而是在每轮协调中由MIMO自主决定下一步行动：

- **dispatch_agents**: 分配任务给合适的Agent
- **revise_plan**: 根据已有执行结果调整后续计划
- **finalize**: 整合所有结果输出最终回答

支持最多5轮协调循环，每轮根据上一轮的执行结果动态调整。

### 3.2 共享黑板机制

所有Agent共享同一个黑板字典，实现跨Agent信息流转：

- CalcAgent计算出装机容量65kW → 写入黑板 `calc_calc_pv_power`
- VisualizationAgent读取后直接生成图表 → 无需重复计算
- 实测复杂查询产生13-22个黑板节点

### 3.3 Agent间自主通信

每个Agent的工具列表注入了 `ask_agent` 工具，当遇到超出自身专业范围的问题时，MIMO会自动调用该工具向其他专家求助：

- EvolutionAgent → MemoryAgent：查询历史记录
- CalcAgent → SearchAgent：搜索行业参数
- 实测验证了完整的跨Agent通信链路

### 3.4 持久化经验积累

AgentMemory将每次任务的经验以JSON持久化到磁盘：

- 经验列表（最近50条）：任务描述、执行结果、成功/失败状态
- 知识字典：自主学习的行业知识
- 偏好设置：Agent的个性化配置
- 统计数据：任务完成数、工具使用次数等
- 新任务处理时自动检索相关历史经验注入上下文，实现跨对话学习

### 3.5 自进化机制

EvolutionAgent实现了系统的自主学习和进化：

- 自动记录运行中的失败案例和知识缺口
- 通过 `auto_learn` 触发自主学习
- 生成技能补丁后通过 `apply_skill_patch` 热更新
- 无需重启即可提升系统能力

### 3.6 53个行业专业工具

基于真实行业公式和参数库封装，而非通用API调用：

- **电价数据库**: 全国各省大工业/商业/居民电价，含峰谷分时
- **光伏参数库**: 各省等效利用小时数、组件功率密度、系统效率
- **碳排放因子库**: 电网平均碳排放因子、标准煤换算系数
- **设备参数库**: 主流组件/逆变器/电池参数和价格

## 四、技术实现细节

### 4.1 Agent自主决策循环（ReAct模式）

每个Agent的 `execute_task()` 方法实现了完整的ReAct循环：

1. MIMO接收任务描述 + 上下文 + 历史经验 + 黑板内容
2. MIMO自主决定调用哪个工具、传入什么参数
3. 工具执行结果注入上下文
4. MIMO根据结果决定下一步（继续调用工具、求助其他Agent、或输出最终回答）
5. 最多5步，每步由MIMO独立决策

### 4.2 动态协调流程

```
用户提问 → Orchestrator(MIMO分析)
    │
    ├─ 简单问题 → 直接dispatch给1个Agent → finalize
    │
    └─ 复杂问题 → dispatch给多个Agent(并行/串行)
                      │
                      ▼ 第1轮执行结果
                    MIMO评估 → 是否需要补充？
                      │
                      ├─ 是 → revise_plan → 第2轮dispatch
                      │                        │
                      │                        ▼ 第2轮结果
                      │                      MIMO评估 → ...
                      │
                      └─ 否 → finalize → 输出最终回答
```

### 4.3 消息协议

Orchestrator与DeepSeek API的通信遵循严格的OpenAI Function Calling消息格式：

- assistant消息包含所有tool_calls
- 每个tool_call对应一条tool响应消息
- 支持单轮多tool_calls的并行调度
